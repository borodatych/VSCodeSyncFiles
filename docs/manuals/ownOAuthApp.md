# Свой OAuth-ключ провайдера — когда и как подключить

← [Документация](../README.md)

> **Отвечает на вопросы:** как подключить свой Client ID; почему упирается в
> лимит API провайдера; можно ли не зависеть от встроенного ключа расширения;
> какой redirect URI прописать в консоли приложения.

Для **Яндекс Диска** и **Dropbox** ключ уже вшит — вход работает сразу после
установки, настраивать ничего не нужно. Для **OneDrive** и **Google Drive**
встроенного ключа нет: там своё приложение обязательно.

Свой ключ нужен, если: вы упираетесь в лимиты запросов, которые делит с вами
весь пул пользователей расширения; политика организации требует собственного
приложения; или вы хотите видеть и отзывать доступ в своей консоли.

Этот мануал — про порядок действий. Что расширение делает с токенами, описано в
[каталоге возможностей](../functional.md), раздел про подключение провайдеров.

---

## Главное условие: ключ публичный, секрет не нужен

Расширение работает как **публичный клиент** (OAuth 2.0 + PKCE и device code).
Client secret никуда не вводится и нигде не хранится — если консоль провайдера
предлагает создать секрет, он вам не понадобится.

Токены лежат в SecretStorage редактора (системная связка ключей ОС), а не в
настройках и не в файлах проекта.

> **Не кладите секреты в настройки проекта:** `settings.json` уезжает в
> репозиторий вместе с кодом. В настройках расширения хранится только Client ID
> — публичный идентификатор, а не пароль.

## Что прописать в консоли провайдера

| Провайдер | Настройка расширения | Redirect URI | Права (scope) |
|---|---|---|---|
| **OneDrive** | `vscodesync.onedriveClientId` | `http://127.0.0.1:8736/oauth-callback` | `Files.ReadWrite offline_access` |
| **Google Drive** | `vscodesync.googleDriveClientId` | `http://127.0.0.1:8737/oauth-callback` | `https://www.googleapis.com/auth/drive.file` |
| **Dropbox** | `vscodesync.dropboxAppKey` | `http://127.0.0.1:8734/oauth-callback` | доступ к файлам приложения |
| **Яндекс Диск** | `vscodesync.yandexOAuthClientId` | `http://127.0.0.1:8735/oauth-callback` | зависит от `vscodesync.yandexUseAppFolder` |

Redirect URI должен совпадать **посимвольно**, включая порт и путь.

## 1. Создать приложение

### OneDrive (Azure)

1. **Azure Portal → Microsoft Entra ID → App registrations → New registration**.
2. Тип аккаунтов — с личными аккаунтами Microsoft, если синхронизируете личный
   OneDrive.
3. **Authentication → Add a platform → Mobile and desktop applications**,
   redirect URI из таблицы выше; включите **Allow public client flows** — без
   этого не сработает вход по коду устройства.
4. Скопируйте **Application (client) ID**.

### Google Drive

1. **Google Cloud Console → APIs & Services**, включите **Google Drive API**.
2. **Credentials → Create credentials → OAuth client ID**, тип —
   **Desktop app**; добавьте redirect URI из таблицы.
3. На экране согласия добавьте scope `drive.file` и себя в тестовые
   пользователи, пока приложение не опубликовано.
4. Скопируйте **Client ID**.

Scope `drive.file` даёт доступ только к файлам, созданным этим приложением, —
остальной Диск расширение не видит.

### Dropbox

1. **Dropbox App Console → Create app**, тип доступа — **App folder** (папка
   приложения) или **Full Dropbox**, если синхронизируете произвольные пути.
2. Вкладка **Settings → Redirect URIs** — добавьте URI из таблицы.
3. Скопируйте **App key**.

### Яндекс Диск

1. **Яндекс OAuth → Создать приложение**, платформа — **Веб-сервисы**, redirect
   URI из таблицы.
2. Права: `cloud_api:disk.app_folder`, если включена настройка
   `vscodesync.yandexUseAppFolder` (файлы лежат в «Приложения/…»), иначе —
   права на чтение и запись всего Диска.
3. Скопируйте **ClientID**.

## 2. Прописать ключ в расширении

1. **Файл → Параметры → Настройки**, найдите `vscodesync` и нужный ключ из
   таблицы (или откройте `settings.json` пользователя).
2. Вставьте идентификатор и сохраните.
3. Выйдите из провайдера и войдите заново — старый токен выдан под прежний
   ключ и работать не будет.

> **Смена ключа требует повторного входа:** пока не переавторизуетесь,
> расширение продолжит ходить со старым токеном, а провайдер начнёт отвечать
> отказом. То же касается смены `vscodesync.yandexUseAppFolder` — меняются
> запрошенные права.

Вернуться на встроенный ключ (Яндекс, Dropbox) можно, очистив настройку.

## Если не работает

| Симптом | Причина и что делать |
|---|---|
| Браузер показывает ошибку redirect URI | URI в консоли не совпадает с таблицей: проверьте порт, `127.0.0.1` вместо `localhost`, путь `/oauth-callback` |
| Вход проходит, но запросы получают отказ | Не выданы права из таблицы, либо после смены ключа не было повторного входа |
| OneDrive: вход по коду устройства не начинается | В Azure не включён **Allow public client flows** |
| Google: «app is blocked» или доступ только у вас | Приложение не опубликовано — добавьте себя в тестовые пользователи |
| Яндекс: после смены `yandexUseAppFolder` файлы «пропали» | Изменился scope и корень хранения (`app:/…` против корня Диска) — файлы лежат в прежнем месте, войдите заново с нужными правами |

## Не путать с вводом токена вручную

Client ID — идентификатор приложения, через которое расширение просит доступ.
Ручной ввод готового OAuth-токена (аварийный путь для Яндекс Диска) — другое:
там вы вставляете уже выданный токен, минуя браузерный вход.

[crossMachinePaths.md](crossMachinePaths.md) — разная структура папок на машинах.
