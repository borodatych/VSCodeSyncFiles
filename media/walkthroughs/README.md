Three short clips embedded in the VSCodeSync «getStarted» walkthrough.
The spec lives in [`src/core/walkthroughVideoSpec.ts`](../../src/core/walkthroughVideoSpec.ts);
this directory holds the actual recordings + their markdown wrappers.

## Files expected here

| File | Generated by |
|---|---|
| `<id>.mp4` | hand-recorded, `.gitignore`d until it exists |
| `<id>.md` | `renderVideoMarkdownBody(spec)`, committed alongside the clip |

Neither is in the repo yet. While a clip is missing, its spec carries
`hasRecording: false` and the walkthrough step falls back to the static
extension icon — the same media every non-video step of the walkthrough uses.

## Adding a recording

1. Record and encode per the brief below; drop `<id>.mp4` in this directory.
2. Flip `hasRecording` to `true` for that spec in
   `src/core/walkthroughVideoSpec.ts`.
3. Write the wrapper: `renderVideoMarkdownBody(spec)` → `<id>.md` here.
4. Point the matching step in `package.json` at
   `"media": { "markdown": "media/walkthroughs/<id>.md" }` and drop `.mp4`
   from `.gitignore`.
5. `npm test` — `walkthroughMediaIntegrity` fails if any referenced file is
   missing, which is exactly the mistake that shipped in v1.0.0/1.0.1.

## Recording brief

Encoder: `ffmpeg -i in.mov -c:v libx264 -crf 23 -preset slow -c:a aac -b:a 96k out.mp4`

- Resolution: 1280×720 (matches retina-2× downscale on most laptops).
- Frame rate: 30 fps; 60 fps for the time-travel clip if scrubbing reads
  unevenly.
- Bit rate: target ≤ 1.5 Mbps so the bundled VSIX stays small.
- Length: hard-cap 30 s per clip — the storyboard is built around it.
- Audio: none (VS Code walkthroughs are silent contexts).
- Captions: bake in localised subtitles as soft titles; do not rely on a
  separate `.vtt` file.

## Storyboards

See `ONBOARDING_VIDEO_SPECS` in `src/core/walkthroughVideoSpec.ts` for the
per-clip scene-by-scene plan. Edit there first, regenerate the `.md`
wrappers, then re-record so the storyboard, narration, and on-screen
moments line up.
